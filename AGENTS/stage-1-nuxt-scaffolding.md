# Stage 1 — Nuxt Scaffolding

## Description

Replace the Vite + Vue SPA bootstrap with a Nuxt 3 application configured for
static client-side-only output. This stage establishes the project skeleton that
all subsequent stages build upon. The app should be runnable locally and deployable
to fly.io before any feature migration begins.

## `Dockerfile` update

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package.json package-lock.json* ./
RUN npm install
COPY . .
ARG VITE_API_BASE_URL=http://localhost:8080
ENV VITE_API_BASE_URL=$VITE_API_BASE_URL
RUN npm run generate        # <-- was: npm run build:plain

FROM nginx:1.27-alpine
COPY nginx/default.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/.output/public /usr/share/nginx/html   # <-- Nuxt output
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

## Success criteria

1. `npm run dev` starts the Nuxt dev server with hot-reload.
2. `npm run generate` produces a static `dist` or `.output/public` folder.
3. Docker build completes successfully and the nginx container serves the app.
4. PWA service worker is registered; Lighthouse PWA audit passes offline criterion.
5. `npm test` passes with no regressions (all existing Vitest tests must pass or be
   explicitly deferred with a TODO comment and a linked issue).
6. Prettier check passes (`npm run format:check`).

- [ ] GitHub Actions workflows pass on a test push.
- [ ] No TypeScript errors (`vue-tsc --noEmit` or Nuxt type check).
- [ ] Existing Vitest test suite passes (or failures are documented as deferred).
